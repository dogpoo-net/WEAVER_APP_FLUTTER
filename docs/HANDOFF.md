# WEAVER 작업 인계

## 설계 방향
첨부 설계 요약을 바탕으로 빠른 기록함을 첫 화면으로 선택했습니다. 따뜻한 아이보리 배경, 잉크색 본문, 절제된 녹색 강조를 사용합니다. 제목 입력 없이 본문의 첫 줄을 목록 제목으로 표시합니다. 모바일은 작성란 우선, 넓은 화면은 목록과 작성란을 함께 배치합니다.

## 구현
- 빠른 메모 추가, 열기, 수정, 본문 검색.
- 공백 메모 방지, Markdown 원문 보존, 저장 피드백.
- 작성 중 다른 메모를 열 때 변경 손실 확인.
- 로그인과 서버 통신 없음.
- 현재 메모리 기반 UI 프로토타입입니다. 앱 재시작 시 메모는 초기화됩니다. 화면에도 이를 표시합니다.

## 다음 단계
Repository 레이어와 로컬 영속 저장을 검증·추가한 뒤 재시작 복원, 저장 실패, 초안 복원을 테스트합니다. SQLite/Drift는 후보이며 아직 확정하지 않았습니다. 이후 Markdown 미리보기, 태그, 노트 링크와 역링크를 추가합니다. 배포용 앱 식별자는 미확정입니다.

## 개발
Flutter 3.47.9 / Dart 3.13.7. 클라우드에서 `bash scripts/setup-cloud.sh` 후 `export PATH="/workspace/toolchains/flutter/bin:$PATH"`로 활성화합니다.

검증: `flutter analyze --no-pub`, `flutter test --no-pub`, `flutter build web --no-pub`.
기존 체크아웃을 사용하고 사용자가 요청하지 않은 worktree는 만들지 않습니다. Android/iOS 실기기 빌드는 아직 검증하지 않았습니다.

## Material 3 테마 업데이트
Flutter 공식 Material 패키지를 사용합니다. 인디고 기반 의미 색상과 표면 단계, 24px 카드 곡률 및 테두리로 영역을 구분합니다. 상단 테마 메뉴에서 시스템 설정/라이트/다크를 선택하며 초기값은 시스템 설정입니다. 선택은 현재 세션에만 유지됩니다. 메모 및 초안은 테마 전환 시 보존됩니다. 테마 설정 영속화는 로컬 저장 단계에 포함합니다.

## 사용자 UX 방향 업데이트
사용자는 Markdown 문법 중심의 편집을 지양합니다. 원문은 그대로 보존하되 화면에서는 포맷 지식 없이 단어와 생각을 작성하게 합니다.

성장 흐름은 **원소단어 → 짧은 노트 → 긴 글**입니다. 원소단어를 저장하고 뜻·설명·사용 맥락을 찾아보는 단어장 역할을 포함합니다. 긴 글 작성 중 현재 입력 중인 단어의 첫 글자부터 저장된 단어와 노트 후보를 제시하는 UX를 다음 단계에서 설계합니다.

후보 제안 설계안: 커서 앞 단어를 기준으로 검색하고, 한글 IME 조합을 방해하지 않으며, 후보는 사용자가 선택할 때만 삽입합니다. 자동 치환하거나 편집 포커스를 빼앗지 않습니다. 후보가 없으면 그대로 작성할 수 있습니다. 선택한 원소단어와 원본 사이 연결은 텍스트와 별도 데이터로 관리하는 방향을 검토합니다. 단어장·자동완성·긴 글 편집은 아직 구현하지 않았습니다.

이번 작은 UI 수정: 명시적인 InkRipple 터치 피드백, 카드 경계 안 리플 클리핑, 검색창 포커스 테두리의 두께·대비 완화, Markdown 안내 제거.

## 문단 작성 도구
빠른 메모 영역의 `문단 쓰기`로 진입합니다. 공백 없는 짧은 메모 제목을 원소단어 후보로 보여주고, 없으면 명시적으로 표시한 예시 단어를 제공합니다. 단어 선택은 현재 문단 커서/선택 영역에 삽입합니다. 비어 있지 않은 문단 오른쪽에 타이틀/부제목/본문 선택 버튼이 나타나며, 기본 역할은 본문입니다. 다음 문단 버튼으로 블록을 추가합니다. 역할과 원문을 별도로 보관하며 저장 후 다시 열면 복원됩니다. 작성 중 닫기에는 손실 확인이 있습니다. 현재 저장은 메모리 기반이며 첫 글자 자동 후보 검색과 영속 단어장은 후속 단계입니다.

## 원소 배지와 후보 UX
문단 쓰기는 빠른 메모 카드 외부 메뉴입니다. 한 단어 메모는 Wrap으로 작은 라운드 배지를 여러 개씩 배치합니다. 단어별 무작위 색조는 실행 세션 내 공유되며 라이트/다크 명도만 달리합니다. 문단 작성 시작 목록과 후보도 같은 배지 컴포넌트를 사용합니다. 커서 앞 토큰의 접두어 및 한글 초성으로 후보를 찾고, 선택한 경우에만 해당 토큰을 완성합니다. 문단 역할은 작은 세로 연결 버튼셋(제목/부제/본문)으로 변경했습니다. 데이터와 배지 색상의 영속 저장은 아직 없습니다.

## 문단 머리와 어시스트 보정
역할 선택은 문단 머리의 작은 가로 연결 버튼셋으로 이동했습니다. 상단 원소 목록 자체가 활성 문단 커서 앞 토큰에 반응하는 어시스트입니다. 빈 입력에서는 전체 후보를 표시하며 중복 하단 후보 영역은 제거했습니다. 한글 조합 중 접두어(예: ㄱ/과/관 → 관찰)도 매칭하고, 입력 원문은 후보를 선택하기 전에는 변경하지 않습니다. 단어 선택 시 후행 공백을 자동 추가하지 않습니다.

## 프로젝트와 완성 글
문단 묶음 저장 후 프로젝트 화면으로 진입합니다. 완성 글 탭은 제목/부제/본문 역할에 맞춰 모든 문단을 하나의 글로 렌더링합니다. 원소 탭은 프로젝트의 후보 목록 조회와 원소 추가를 제공하며, 문단 탭은 전체 문단을 표시하고 편집기로 연결합니다. 프로젝트 생성 시 기록함의 원소를 복사하고 이후 프로젝트별로 관리합니다. 메모리 기반이며 재시작 후 복원은 아직 미지원입니다.

역할 버튼은 빈 문단에도 즉시 표시됩니다. 원소 어시스트는 EditableText의 커서 좌표를 사용한 Overlay 팝업으로 제공하며 본문 레이아웃을 밀지 않습니다. 빈 입력에서 전체 후보를 보여주고 선택 후 팝업을 닫습니다. 닫기 버튼과 스크롤 시 정리를 지원하며, 하단 공간이 부족하면 커서 위로 배치합니다.

## 선택 기반 프로젝트 생성
문단 저장은 프로젝트를 자동 생성하지 않습니다. 별도 프로젝트 생성 화면에서 저장된 문단을 제목/부제/본문 필터로 찾아 선택합니다. 제목은 최대 하나이며 선택한 순서대로 프로젝트 문단이 구성됩니다. 선택 해제 후 다시 선택하면 끝에 추가됩니다. 제목을 선택하면 이름이 자동 입력되며 직접 편집한 이름은 이후 선택 변경에도 보존됩니다. 이름과 선택 문단이 있어야 생성할 수 있습니다. 프로젝트 이름은 본문과 별도 필드입니다. 프로젝트 전체 글 화면의 명칭은 미리보기로 변경했습니다.

## 작업공간 메뉴
메인 좌측 상단 격자 버튼은 메뉴 모달을 엽니다. 메인/문단 쓰기를 고정하고 구분선 아래 프로젝트 목록만 Expanded + ListView로 독립 스크롤합니다. 프로젝트 선택 시 해당 프로젝트로 이동합니다. 모바일에서 메뉴가 가용 높이에 맞게 줄어들며 긴 이름은 말줄임합니다. 본문 소개 문구·반복 안내를 축소했고, 작업 버튼을 Wrap에 배치하고 데스크톱 열의 내부 여백을 24px로 맞췄습니다.

## 저장·미리보기 및 RTL 기반
저장 액션 명칭을 저장으로 통일했습니다. 프로젝트 문단 편집의 AppBar에서 미리보기를 저장 앞에 배치하고 미저장 원문·역할로 읽기 전용 화면을 만듭니다. 뒤로 돌아오면 초안은 유지됩니다.

어시스트는 스크롤과 window metrics(키보드) 변화에 위치를 재계산하며, 가용 화면 안에서 높이를 제한합니다. 공간이 있으면 진행 방향 옆, 부족하면 가시 영역 안으로 이동합니다. RTL에서는 반대쪽을 우선합니다. 메뉴와 역할 버튼은 AlignmentDirectional/EdgeInsetsDirectional을 사용합니다. 후보 토큰은 아랍어 등 비라틴 문자도 처리합니다. RTL+키보드+스크롤 위젯 테스트를 추가했습니다. 현재 UI 번역 및 locale 선택은 아직 제공하지 않으며, 문자열 리소스 분리와 공식 localization delegates 연결은 국제화 단계에서 추가해야 합니다.

## 구절 원소 및 상단 어시스트
원소는 공백 없는 단어로 제한하지 않습니다. 일반 빠른 메모 전체 원문(앞뒤 공백 제외)을 원소 배지와 후보로 사용하며, 프로젝트/문단 묶음은 구분합니다. 공백·길이 제한 필터를 제거했습니다. 어시스트는 커서 위쪽을 우선하고 키보드 위 가용 높이로 제한합니다. 팝업 내부 스크롤 알림은 외부 위치 재계산으로 전파하지 않습니다.

## 독립 문단·글로벌 원소·메타데이터
문단 편집기에서 여러 문단을 저장해도 기록함에는 각각 독립 항목으로 저장합니다. 원소는 앱 세션의 ElementStore가 공유하며 프로젝트에서 추가한 원소도 기록함과 다른 편집기에서 접근합니다. 공백 포함 원문과 첫 생성 시각·ID를 보존하며 같은 원문 재등록은 중복 생성하지 않습니다. 구절 입력 중 공백 뒤에서도 긴 접두어를 우선하여 후보를 완성합니다.

프로젝트 원소 탭은 현재 프로젝트 문단에서 일치하는 원소만 표시합니다. 글로벌 추가와 프로젝트 사용 여부는 별개입니다. 미리보기는 원소 고유 색상의 링크를 표시하고 링크/원소 배지를 누르면 생성 시각, 사용 횟수, 위치, 동시 등장 원소 순위를 표시합니다. 집계는 현재 저장된 독립 문단 및 프로젝트 문단 각각의 원문 문자열 일치로 계산하며, 겹치는 일치는 긴 원소 우선입니다. 동일 문단이 독립 항목과 프로젝트에 있으면 각 사용 위치로 계산합니다. 동시 등장은 같은 문단에 등장한 원소별 문단 수입니다. 직접 입력과 후보 삽입을 구분하는 이벤트 이력은 아직 없습니다. 앱 재시작 시 원소·생성 시각·프로젝트 모두 초기화되는 메모리 프로토타입이므로 영속 저장/마이그레이션을 다음 우선 과제로 둡니다.

## 메타데이터 표시·집계 범위 정리
모달은 원소 색상 배지를 제목으로 표시하고 생성일/프로젝트 사용/사용 위치/함께 쓰인 원소를 구분선으로 나눕니다. 동시 등장 원소도 같은 색상 배지로 표시합니다. 사용 횟수·위치·동시 등장 집계는 isProject=true인 출처만 대상으로 하며 독립 문단은 제외합니다. 같은 프로젝트 내 여러 등장 위치는 각각의 등장 횟수로 계산합니다. 미리보기 링크는 TextDecorationStyle.dotted와 원소 배지 배경색을 사용합니다.

## 현재 기준: 데스크톱 어시스트·영속 저장·초기화
앞선 메모리 전용 안내는 이 변경으로 대체합니다. SharedPreferences에 버전 1 JSON 스냅샷을 기록하고 저장한 원소·문단·프로젝트·생성 시각·색상을 복원합니다. 저장은 순차 처리하며 이전 스냅샷을 별도 키에 보관합니다. 읽기 실패 시 자동 덮어쓰기를 차단하고 오류를 표시합니다. 백업 복원은 파일 전체를 검증한 뒤 확인을 받으며, 형식/버전 오류 시 원본을 유지합니다. 저장 전 초안·테마 설정은 대상이 아닙니다. 초기화는 저장 대기열 이후 현재 키와 이전 키를 제거하고 메모리를 비웁니다. 웹 JSON 다운로드/업로드는 file_selector/cross_file를 사용합니다. 실제 Chromium에서 새로고침 복원, 다운로드, 초기화, JSON 복원을 검증했습니다.

검색은 커서 앞 현재 토큰 기준이며 한 글자는 접두어, 두 글자 이상은 contains, 접두어 우선 정렬입니다. 데스크톱(폭 760px 이상, 소프트 키보드 없음)은 32px 행 목록과 방향키/Enter/Space/Escape를 지원합니다. 조합 중 키 입력은 IME에 넘깁니다. 모바일 위쪽 배지 팝업은 유지합니다. 공백을 포함한 원소도 두 글자 이상 부분 검색으로 찾을 수 있습니다.

## 해시태그
원소 입력의 공백 경계 #태그를 추출하여 ElementRecord.tags에 분리 저장합니다. 태그는 소문자 정규화·중복 제거하며 C#처럼 단어 중간 #는 유지합니다. 같은 원소 재등록 시 태그를 합치고 기록함에서 편집한 경우 전달한 태그로 갱신합니다. 메뉴의 프로젝트 내부 스크롤 영역 아래에 해시태그 목록을 표시합니다. 태그 상세는 연결된 원소와 해당 원소가 실제 매칭되는 문단·프로젝트를 나열하고 원문 열기로 연결합니다. JSON v1의 tags는 선택 필드이므로 이전 백업은 빈 태그 목록으로 복원합니다.

## 배지 어시스트·삭제·폴더
데스크톱 후보는 Wrap 배지로 복원. Ctrl+방향키만 후보 제어, Ctrl+Enter/Space 삽입, Ctrl 해제 시 일반 편집. 원소 메타데이터에서 확인 후 글로벌 삭제, 원문 보존. 메인 배지 길게 누르기로 메타데이터 접근. 프로젝트 폴더는 단일 계층: 메뉴 생성, 프로젝트 앱바 이동. v1 JSON에 optional folders 및 project.folder 추가하여 기존 백업 호환.
메인 화면 너비 1000px 이상에서는 왼쪽 메뉴 기본 표시. 메뉴 숨기기 후 아이콘으로 같은 왼쪽 모달을 열고 고정 버튼으로 복원. 좁은 화면은 기존 모달 유지, RTL에서는 시작 방향을 따름.

모바일 어시스트: 커서 좌표에 따른 높이 계산 제거. 키보드 위 시작 방향에 고정, 높이는 가용 화면의 40%(최대180px). 문단 편집 viewport 하단에 같은 공간을 확보해 커서/다음 내용이 패널에 가리지 않게 함. 후보 내부 스크롤과 편집 스크롤 분리.

데스크톱 어시스트 최신 동작: Ctrl 단독 키업으로 입력/선택 모드 토글. Ctrl 조합 단축키는 토글하지 않음. 선택 모드 방향키는 렌더링된 배지 좌표 기반(상하 인접 행의 가장 가까운 가로 위치), Enter/Space 삽입 후 입력 복귀. Escape 또는 일반 타이핑도 입력 복귀. 선택 후보 자동 내부 스크롤.

원소 사용 위치: ElementSource에 project/paragraphIndex를 인덱싱(복원 시 재생성). 출현별 링크가 ProjectPage initialParagraph/initialOffset으로 이동해 원소 링크 autofocus 및 ensureVisible. 동명이 프로젝트/반복 출현 구분. WidgetSpan ElementLink로 키보드 포커스, 둥근 1px 테두리, 기존 점선 밑줄 유지. 기본 테마 dark. 폴더 만들기 버튼은 프로젝트 제목 옆 아이콘으로 축소.

한글 폰트: Google Fonts 공식 NotoSansKR[wght].ttf 원본을 NotoSansKR-Variable.ttf로 번들. OFL 라이선스/출처/해시 동봉. main()에서 FontLoader 로딩 완료 후 runApp, ThemeData.fontFamily=NotoSansKR. 한글 11172자 및 현대 조합 자모 전체 cmap 검증.

원소 편집: 메인 클릭은 메타데이터 모달. Stateful 모달 textarea + 저장, 닫으면 미저장 편집 폐기. ElementStore.update는 빈 내용/중복 검사 후 기존 레코드 ID/createdAt/색상 유지하며 tags 교체. onRenamed로 빠른 메모와 project.words 동기화 후 notifyListeners로 영속화. 프로젝트 및 독립 문단 원문은 보존(사용 통계는 수정된 원소 텍스트의 현재 출현으로 계산).

메뉴 DnD: 프로젝트/태그 payload 구분, 교차 드롭 차단, 폴더 및 미분류 drop target. 데스크톱 Draggable/모바일 LongPressDraggable, 드래그 중 가장자리 자동 스크롤. Stateful 메뉴가 모달에서도 이동 즉시 반영, root 콜백으로 영속화. v1 JSON optional hashtagFolders/hashtagFolderAssignments 추가, legacy 기본 빈 값, 초기화 포함.

IME Ctrl 재수정: 논리키가 Process로 전달되는 경우에도 physical ControlLeft/ControlRight로 토글 인식. Chromium DOM compositionstart/update/input + key Process/code ControlLeft 이벤트로 한 번 토글 및 복귀 확인. 사용자 OS의 실제 IME 전체 조합을 자동 재현한 것은 아님.

최신 저장 정책: JSON 파일 내보내기/가져오기 UI·코드 및 file_selector 의존성 제거. 브라우저 자동 저장과 초기화 유지. WorkspaceSnapshot JSON은 내부 저장 직렬화 용도로 유지하여 기존 저장 데이터 호환. 이전 백업/파일 복원 안내는 더 이상 적용되지 않음.

문단 편집 화면: 어시스트를 위해 추가했던 동적 하단 Padding 제거. Scaffold 기본 키보드 resize만 사용하며 편집 ListView는 키보드 위까지 전체 높이를 사용. 모바일 어시스트 overlay 위치는 유지.

키보드 표시 시 문단 목록: inset 증가 또는 모바일 viewport 축소를 감지하고 리사이즈/기본 커서 스크롤 완료 후 목록 maxScrollExtent로 이동. 스크롤 가능한 목록 끝에 어시스트 가림 영역만큼 여유를 추가(본문 viewport를 줄이는 외부 Padding은 없음). 수동 스크롤은 유지, 닫힐 때/폐기 시 예약 취소.
