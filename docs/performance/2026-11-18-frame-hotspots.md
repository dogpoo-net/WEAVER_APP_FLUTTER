# 대량 데이터 렌더링 최적화 (2026-11-18)

## 확인 및 수정

- 메모 링크 렌더링마다 전체 메모를 순회하던 ID 검색을 인덱스로 변경했다.
  직접 Map 수정, 복원, 이름 변경, 삭제, 워크스페이스 초기화에도 인덱스를 유지한다.
- 캔버스 라벨 너비를 매번 TextPainter로 측정하던 경로에 최대 2,048개 LRU 캐시를 적용했다.
  텍스트·방향·글자 배율을 키로 쓰고 시스템 폰트 변경 시 비운다.
- 한 메모의 댓글 개수 변경으로 모든 뱃지/캔버스 메모 본문이 재구성되던 경로를
  해당 메모의 개수가 달라질 때만 재구성하도록 변경했다.
- 동시에 요청된 status/read 조회는 진행 중인 동일 조회를 공유한다.
  저장 요청은 합치지 않으며, 완료 후 새 조회는 다시 실행한다.
- 뱃지 공간 채우기에서 들어가지 않는 항목마다 같은 빈 영역을 다시 정렬하지 않는다.
  중요 생각 전체 표시와 뒤쪽의 작은 뱃지가 빈틈을 채우는 동작은 유지한다.
- 메모 이름 변경 시 문서마다 생성하던 동일 ID→본문 맵은 한 번만 생성한다.

## 재현 및 측정

`flutter test test/frame_hotspots_test.dart --reporter expanded`

Flutter VM 테스트, 첫 실행 제외 5회 중앙값. 동일 환경에서 테스트 파일을 단독 실행했다.
브라우저 FPS, 사용자 기기, 네트워크 지연 측정 결과가 아니다.

| 작업 | 변경 전 | 변경 후 |
|---|---:|---:|
| 메모 5,000개, 링크 ID 조회 10,000회 | 575.321ms | 1.591ms |
| 라벨 100종 너비 측정 2,000회 | 24.952ms | 9.810ms |

`performance_regressions_test.dart`는 뱃지 1,000개 중 댓글이 달라진 1개만
재구성되는지, 동시 조회 10개가 1회 요청으로 합쳐지는지, 이후 조회가 다시
실행되는지, ID 인덱스 및 라벨 배율 변경을 검사한다.

관련 테스트 64개와 벤치마크 2개 통과, flutter analyze 오류 없음.
자동 저장, 늦은 서버 응답과 로컬 변경의 경합, 캔버스 이동·라벨·링크,
중요 생각 배치, 삭제, 수동 동기화 검토의 기존 테스트를 포함한다.

## 남은 측정 범위

캔버스 자체는 전체 개체의 배치·가림·연결선 계산이 남아 있다. 이번 변경으로
특정 기기의 목표 FPS를 보장하지 않는다. 사용자 데이터 규모에서 여전히
프레임 저하가 있으면 브라우저 performance trace로 build/layout/raster 비중을
측정하고 화면 밖 개체 가상화를 별도로 검토한다.
